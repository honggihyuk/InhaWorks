# InhaWorks 디자인 시스템 (design.md)

> 화면을 새로 만들거나 고칠 때 따르는 규칙입니다. 실제 값은 `src/main/resources/static/css/app.css` 가 기준이고,
> 이 문서는 그 값을 언제·어떻게 쓰는지 정리한 것입니다. (2026-11-19 기준)

## 1. 원칙

| 원칙 | 뜻 |
|---|---|
| **흰 바탕 · 검은 글자** | 바탕은 흰색, 글자는 거의 검정(#0B0F19). 회색 배경 박스를 남발하지 않는다 |
| **연한 파랑은 보조** | 선택된 메뉴, 안내 박스, 칩, 진행 막대 같은 보조 요소에만 연한 파랑을 쓴다 |
| **진한 파랑은 아껴서** | 파랑(#2563EB)은 **핵심 숫자**와 **주 버튼**에만. 한 화면에 주 버튼은 보통 하나 |
| **빨강은 문제일 때만** | 재작업·반려·DEAD·실패·삭제처럼 사람이 확인해야 하는 것에만 |
| **절제 · 여백 · 위계** | 장식 대신 여백과 글자 크기로 구분한다 (Apple 디자인 원칙) |
| **되돌릴 수 없는 일은 한 번 더 묻는다** | 삭제·반려·재처리 등은 확인 모달. 되돌릴 수 있는 일은 토스트 + 실행 취소 |

## 3. 화면 틀 (`templates/layouts/layout.html`)

```
┌──────────┬──────────────────────────────────────────┐
│ 사이드바  │ 상단바 (반투명 · 블러) : 브레드크럼 · 🔔        │
│ 메뉴      ├──────────────────────────────────────────┤
│          │ 본문 .content (머리말 → 카드들)              │
│ 상태 카드 │                                          │
│ 내 정보   │                                          │
└──────────┴──────────────────────────────────────────┘
```

- **사이드바** : 흰 바탕 + 오른쪽 테두리. 선택된 메뉴는 `#EEF4FF` 바탕 + `#D6E4FF` 테두리, 아이콘만 파랑.
  - 관리자 : 업무(대시보드, 할 일, 보고서, 결재함 배지, 게시판) / 근태(**출퇴근 · 스케줄 · 휴가** 세 메뉴, 휴가에 승인 대기 배지) / 관리(재처리 모니터 + 빨간 DEAD 배지, 직원·조직)
  - 직원 : 우리 회사(홈, 할 일, 보고서, 게시판, 출퇴근, 스케줄, 휴가, 알림)
  - 근태는 예전처럼 한 메뉴 안의 세그먼트 탭으로 묶지 않는다. 메뉴 하나 = 화면 하나, 주소는 그대로(`/attendance`·`/schedule`·`/leave`, 관리자 `/admin/…`)
  - 아래 : 관리자 상태 카드("스케줄러 정상 · 다음 자동 배정 · 대기 이벤트") + 내 정보 · 로그아웃
  - 배지 숫자는 `LayoutModelAdvice` 가 넣는다 (`navInbox`, `navReviewWaiting`, `navDead` …)
- **상단바** : `rgba(255,255,255,.72)` + `backdrop-filter: blur(20px) saturate(180%)`, 화면 위에 붙어 있음. 각 화면이 `layout:fragment="crumbs"` 로 위치를 적는다 (예: 관리자 › 할 일 › 직원별 현황).
- **본문 머리말** `.page-header` : 위 작은 글(날짜·분류) → h1 → 설명, 오른쪽에 버튼 묶음 `.actions`.

새 화면 템플릿의 기본 모양 :

```html
<html xmlns:th="http://www.thymeleaf.org" xmlns:layout="http://www.ultraq.net.nz/thymeleaf/layout"
      layout:decorate="~{layouts/layout}">
<head><title>화면 이름</title></head>
<body>
<nav layout:fragment="crumbs" class="crumbs" aria-label="현재 위치"><span>관리자</span><span class="sep">›</span><b>화면 이름</b></nav>
<main layout:fragment="content" class="content">
    <div class="page-header"><div><h1 class="page-title">화면 이름</h1><p class="page-sub">설명</p></div>
        <div class="actions"><a class="btn primary" href="#">주 동작</a></div></div>
    <section class="card"><div class="card-head"><h2>카드 제목</h2></div> … </section>
</main>
</body>
</html>
```

## 4. 구성 요소

### 4.1 카드와 숫자

| 클래스 | 쓰임 |
|---|---|
| `.card` / `.card.flush` (표가 꽉 차게) / `.card.soft` (연한 파랑, 안내·검수 박스) | 모든 내용 묶음 |
| `.card.hero` | 대시보드 첫 카드 (2칸 차지, 연한 파랑, 64px 파란 숫자 + 파란 막대) |
| `.card.kpi` + `.label` `.value` `.foot` | KPI. 핵심 지표만 `.value.blue`, 문제는 `.value.red` |
| `.grid.grid-2/3/4`, `.split` (본문 + 오른쪽 360px), `.split.left-list` (왼쪽 목록 340px) | 배치 |

대시보드 KPI는 히어로 1개 + 카드 2개까지만. 숫자를 늘어놓지 않는다.

### 4.2 표와 긴 목록

- 목록 표는 `.card.flush > .table-box > table.t` 로 쓴다
- 머리 12px/600 회색, 칸 16px 20px, 행 호버 `#FAFCFF`, 고정 공지 행 `.pinned` (연한 파랑), 흐리게 `.dim` (중지·종료)
- 행 끝 메뉴는 ⋯ 아이콘 버튼 (`data-menu-trigger`)

**넓은 화면 (901px~)**

- 표 상자는 **세로로 따로 스크롤하지 않는다.** 페이지 전체가 스크롤되고, 머리행(`thead th`)은 `position: sticky; top: var(--topbar-h)` 로 상단바(56px) 바로 아래에 붙는다 (흰 배경 + 아래 경계선 `inset box-shadow`)
- 그래서 표를 감싸는 상자는 스크롤 상자가 되면 안 된다 : `.table-box` 는 `overflow-x: clip`, `.card.flush` 는 `overflow: clip` (`hidden`/`auto` 는 sticky 를 끊는다)
- 칸이 좁으면 글자가 줄바꿈된다. 가로 스크롤이 꼭 필요한 표(달력·주간표)만 `.table-box.scroll-x` 를 쓴다 — 이 표는 머리행 고정·카드 전환을 하지 않는다
- 표 안의 ⋯ 메뉴는 `position: fixed` 로 버튼 위치에 띄운다(`app.js`). 상자 안에서 잘리거나 스크롤을 만들지 않고, 아래 공간이 모자라면 위로 열린다. 페이지를 스크롤하거나 창 크기를 바꾸면 닫힌다

**좁은 화면 (~900px) : 카드 목록**

- `app.js` 가 `.table-box` 에 `.cards` 를 붙여 바꾼다. 900px 이하이거나, 넓은 화면이라도 표가 상자 폭에 다 들어가지 않을 때(사이드바가 있는 900~1150px 등) 카드가 된다 — 표를 잘라 내거나 가로 스크롤을 만들지 않는다. 창·상자 폭이 바뀌면 다시 판단
- 머리행을 숨기고 행마다 카드 한 장. 페이지 전체가 스크롤되고 상단바만 고정
- 카드 안 순서 : 제목(굵게) → 상태 칩 → 진행률 막대 + "오늘 n% · x/y" → 보조 정보 한 줄("배정 · 검수 · 주기") , ⋯ 버튼은 오른쪽 위 40px
- 같은 마크업을 CSS 로 바꾼다. `app.js` 가 `thead` 글자로 각 칸의 `data-label`(칸 이름)을 채우고, 첫 칸은 제목(`cell-title`), 머리 글자 없는 칸은 동작 칸(`cell-act`), ⋯ 칸은 `cell-menu` 로 표시한다
- 템플릿에서 직접 고칠 때 : `data-label=""` 이름 없이, `data-label="검수"` 짧은 이름, `class="cell-title"` 제목 칸 지정, `class="cell-meta"` 보조 정보 한 줄로 ( · 로 이어짐), `class="cell-auto"` 한 줄에 나란히, `.m-only` 카드에서만 보이는 글자
- 링크, ⋯ 메뉴, 확인 모달, 세그먼트 필터(`hidden` 행)는 두 모드에서 똑같이 동작해야 한다

### 4.3 상태 칩 (`fragments/ui :: chip(code, label)`)

상태 이름(enum)만 넘기면 색이 정해진다. 직접 색을 고르지 않는다.

| 색 | 상태 |
|---|---|
| 파랑 채움 `.chip.solid` | APPROVED(검수 통과·검토완료·승인), RESOLVED, COMPLETED, DONE, 공지 |
| 빨강 `.chip.red` | REWORK, REJECTED, DEAD, FAILED, OPEN(미해결) |
| 회색 `.chip.grey` | NOT_SUBMITTED(미완료), WAITING, PENDING, CANCELED |
| 연한 파랑 `.chip.blue` | 그 밖의 진행 중 (검수 대기중, 검토중, 제출완료, 처리 중 …) |
| 테두리만 `.chip.outline` | 정보 (항목 6개, #해시태그, 항목 종류) |

### 4.4 버튼

| 클래스 | 쓰임 |
|---|---|
| `.btn.primary` (파랑) | 화면의 주 동작 하나 : 저장, 제출, 승인, 검수 통과, 배정 |
| `.btn.soft` (연한 파랑) | 보조 이동 : 결재함, 검수 대기함, 댓글 등록 |
| `.btn` (흰색) | 일반 : 취소, 이전/다음, 수정 |
| `.btn.danger` (빨간 테두리) | 되돌리기 어려운 동작 : 삭제, 반려, 재작업 요청, 퇴사 처리 |
| `.btn.dark` (검정) | 퇴근하기처럼 주 동작과 짝을 이루는 강한 동작 |
| `.btn.ghost` | 표 안의 가벼운 동작 : 보기, 지우기 |
| 크기 `.sm` / `.lg` / `.block` | 표 안 / 제출 버튼 / 꽉 차게 |

누르면 `scale(.97)` 100ms, 키보드 포커스는 2px 파란 테두리.

### 4.5 입력

- `.field` > `label` + `.input` / `.select` / `.textarea`, 오류는 `.field-error` (빨강 12px)
- 체크 목록 `.check-grid` > `.check` (체크되면 연한 파랑), 요일·선택지 `.toggle-chips`
- 예/아니오 `.yn` (둥근 토글 2개), 사진 `.photo-pick` (점선 상자 + 미리보기), 서명 `canvas.sig-pad`
- 할 일·보고서 작성 폼은 `.task-form` : **파란 머리**(제목·날짜·상태) + 재작업 사유 `.banner-red` + 가이드 `.guide` + 항목 `.q-card` + 큰 제출 버튼
- 입력 이름은 서버와 약속된 그대로 : `item_{ID}` / `field_{ID}`, 파일 `file_{ID}`, 서명 `sig_{ID}`, 중복 방지 `submitToken`

### 4.6 폼 빌더 (할 일 · 보고서 양식)

- 항목 카드 `.f-card` : 번호 · 종류 칩 · 질문 · 필수/선택 · (객관식만) 선택지
- 아래 점선 버튼 `.add-btn` "+ 항목 추가" → 종류 메뉴 `.type-menu`
- 수정할 때 기존 항목은 숨은 `itemIds` / `fieldIds` 로 구분 (종류는 바꾸지 않는다)

### 4.7 세그먼트 · 탭

- `.segmented` : 같은 데이터의 다른 보기 (전체/진행 중/일시중지/종료, 주별/월별, 양식 빌더/제출 현황, 출퇴근/스케줄/휴가)
- `.tabs-line` : 게시판처럼 서로 다른 목록 사이 이동

### 4.8 목록-상세 (결재함, 오늘 할 일, 검수 대기함)

넓은 화면(1101px~)에서는 왼쪽 목록 `[data-md-item]` 을 누르면 오른쪽 `[data-md-pane]` 에 상세 화면의 `[data-md-content]` 부분을 불러온다. 좁은 화면에서는 그냥 상세 화면으로 이동.

### 4.9 달력 · 주간표

- 주간 스케줄(리스트) `table.week` : 오늘 열 연한 파랑, 근무는 `.shift-pill` (근무 유형 이름 + 시각, 유형 색), 마지막 열 "주 근로" — 소정근로 초과는 파란 칩, **주 52시간 초과는 빨간 칩**
- 월별 스케줄(캘린더) `table.month-cal` : 월요일 시작, 지난·다음 달 날짜는 흐리게(`.out`), 오늘 연한 파랑, 칸의 + 로 배정 폼 날짜 채우기. 관리자 캘린더는 같은 근무 유형끼리 묶은 색 블록 `.shift-block` (이름 · 시각 · 인원, 아래 사람 이름 + × 지우기)
- 두 표 모두 `.table-box.scroll-x` (가로 스크롤, 카드 전환 안 함)

### 4.11 근무제 · 근무 유형 (스케줄)

- **근무제 탭** `.policy-tabs > .policy-tab` : 전체 + 정책마다 색 점 · 이름 · 소속 직원 얼굴(최대 3) · 인원, 끝에 점선 "+ 근무제". 고른 탭은 연한 파랑 바탕. 좁은 화면에서는 가로로 넘긴다
- **근무제 카드** `.policy-card` : 근무제 종류 칩 → "1주 소정근로시간 : N시간" → 요약 표 `.policy-facts`(근무 요일 · 하루 소정근로 · 근무시간 · 휴게 · 근무지, 좁은 화면 2열) → 근무 유형 칩(캘린더에서는 눌러서 그 유형만 보기)
- **색** : 근무제·근무 유형 구분에만 연한 파스텔 `.tone-blue / teal / green / yellow / orange / red / pink / purple / grey` (바탕 아주 연하게, 글자만 진하게). 화면의 주 동작·핵심 숫자 파랑 규칙은 그대로
- 근무제 종류(`WorkPolicyType`)마다 기본 색 : 고정 회색 · 시차 파랑 · 선택 보라 · 탄력 청록 · 스케줄 노랑 · 재량 초록 · 간주 주황. 정책·근무 유형마다 바꿀 수 있다
- 직원 목록·리스트의 근무제 칩은 짧은 이름(`shortLabel` : 탄력 근로, 재량 근로, 간주 근로, 선택 근로 …)
- 배정 폼 : 직원을 고르면 그 직원 근무제의 근무 유형만 보인다(`[data-shift-form]`). 유형을 고르면 시각이 채워지고, 휴무는 시각 칸이 잠긴다. 주 52시간을 넘기면 저장 뒤 빨간 토스트로 알린다
- 지우기는 모두 확인 모달 : 근무 유형 지우기(배정된 근무는 시간·이름이 남는다), 정책 지우기(소속 직원이 있으면 막는다), 직원 옮기기

### 4.12 직원 허브 · 인사 서류

- 직원 목록의 이름 → 직원 허브. 머리(큰 아바타 · 이름 · 소속 · 상태 칩들) 아래 밑줄 탭 `.tabs-line.hub-tabs` : 정보 · 근태 · 업무 · 서류 · 이력
- 인사 정보 `.kv-group`(연한 회색 띠 "기본 정보") + `.kv`(라벨 회색 13px / 값 500)
- 근태 : 출근율 도넛 `.donut`(`--p` 퍼센트, 파랑 한 가지) + 달력 `.att-day.st-*` — 출근 파랑 채움(이 화면의 핵심 숫자), 지각 연노랑, 휴가 연초록, 결근 연한 빨강 테두리, 휴무·기록 없음 회색, 예정 연파랑 테두리
- 서류 `.doc-row` : 문서 아이콘 · 이름 · 필수 칩 · 열람 권한 칩(‘관리자만 열람’만 빨강) · 파일 링크 · 오른쪽 "✓ 첨부 완료"(연초록) + 교체/지우기. 필수 미제출은 아이콘이 연한 빨강 + "⚠ 필수 서류예요" 한 줄, **제출 버튼은 필수 미제출일 때만 파랑**
- 인사 서류 파일은 `/uploads/**`(공개) 가 아니라 `app.private-dir` 에 두고 `/hr/docs/{id}/file` 에서 권한 확인 후 내려준다 (`no-store`)

### 4.14 로그인 (`member/login`, `admin/login`)

- 세 겹 : 뒤 `.auth-backdrop`(앱 화면 모양 : 사이드바 + 상단바 + 관리자는 대시보드 / 직원은 홈) → 가운데 흐림 막 `.auth-scrim` → 로그인 카드 `.auth-card`
- 뒤 화면은 `fragments/auth-backdrop :: backdrop('admin' | 'member')` 의 **정적 예시**다. 로그인 전이므로 DB 데이터를 쓰지 않고, 숫자 몇 개 외에는 회색 막대(`.sk`) 스켈레톤
- 뒤 화면은 `aria-hidden="true"` + `inert` + `pointer-events: none` : 화면 읽기·Tab·클릭이 들어가지 않는다. 페이지는 스크롤하지 않고, 카드가 화면보다 길면 막 안에서만 스크롤
- 흐림 막 : `backdrop-filter: blur(10px) saturate(160%)` (+ `-webkit-`), 흰색 45% 바탕. 지원하지 않는 브라우저(`@supports not`)와 `prefers-reduced-transparency` 에서는 거의 불투명한 연파랑 흰 바탕
- 카드 : 흰 바탕 · 20px 모서리 · 큰 그림자, 0.32초 동안 살짝 떠오르며 나타난다 (`prefers-reduced-motion` 이면 흐려지기만). 폼·오류·로그아웃 안내·CSRF 는 그대로

### 4.13 이슈 & 해결

- 지점 칩 → 통계 카드 2장 `.istat` (왼쪽 색 칸 : 처리 대기 연한 빨강 / 해결 완료 연한 파랑, 오른쪽 흰 칸 : 평균·최장 일) → 상태 세그먼트 + 분류 select → 카드 목록 `.issue-card`
- 상세 `.issue-detail` : 상태 배너(처리 대기 연한 빨강 + 진한 칩, 해결 완료 연한 파랑 + 파란 칩) → 제목 24px → "분류 | 지점" → 작성자·시각 → 타임라인 `.timeline` (이슈 = 빨간 ! 점과 연한 빨강 세로선, 해결 = 파란 ✓, 대기 = 점선 원 + 해결 등록 폼)
- 첨부는 이미지면 84px 썸네일 `.att-thumb`, 문서면 파일 카드 `.att-file`(이름 + 확장자)
- 빨강은 처리 대기 표시와 3일 넘은 경과일에만. 해결 취소는 확인 모달

### 4.10 대시보드 전용

- 근무지별 퍼널 `.funnel-row` : 배정 → 제출 완료 → 검수 대기 → 재작업 필요(빨강) → 검수 통과

## 5. 상호작용 규칙 (`static/js/app.js`)

### 5.1 확인 모달 — 이럴 때는 꼭 묻는다

`window.confirm` 을 쓰지 않는다. 버튼(또는 form)에 속성을 달면 `app.js` 가 모달을 띄운다.

```html
<button type="submit" class="btn danger"
        data-confirm="이 할 일을 삭제할까요?"
        data-confirm-body="지난 기록은 남아요."
        data-confirm-ok="삭제" data-danger
        data-reason="reason" data-reason-label="사유 (필수)">삭제</button>
```

| 묻는 동작 | 사유 입력 |
|---|---|
| 삭제(할 일·팀·근무지·게시판·글·근무), 일시중지·사용 중지, 퇴사 처리 | - |
| 반려(보고서·휴가), 재작업 요청 | **필수** (채워야 확인 버튼이 켜짐) |
| Outbox 재처리, 배치 재실행·복구, 미완료 푸시 | - |

### 5.2 토스트

- 서버 메시지(`adminMessage`, `todoMessage`, `reportMessage` …)는 오른쪽 아래 반투명 검은 토스트로 보인다 (오류는 빨강)
- 되돌릴 수 있는 동작(검수 통과, 승인)은 토스트에 **실행 취소** 버튼 (`undoUrl`, 10분 안)
- 제자리 처리 폼은 `data-async="메시지"` (+ `data-undo="주소"`) → 처리 후 새로고침하고 토스트

### 5.3 그 밖

- `data-once` : 제출하면 버튼 잠금 (서버도 토큰으로 한 번 더 막음)
- ⋯ 메뉴는 누른 자리에서 커지며 열린다 (`transform-origin`), Esc·바깥 클릭으로 닫힘. 표 안의 메뉴는 화면 기준(fixed)으로 뜬다 (4.2)
- 모달은 흐린 배경 위에 짧게 커지며 나타나고, Tab 키가 모달 안에서만 돈다

## 6. 접근성 · 움직임

- 모든 입력에 `label` (보이지 않게 할 때는 `.sr-only`), 아이콘 버튼에 `aria-label`
- 현재 메뉴·탭에 `aria-current`, 진행 막대에 `role="progressbar"` + 값
- `prefers-reduced-motion` : 크기 변화 없이 흐려지기만
- `prefers-reduced-transparency` : 반투명·블러 대신 불투명
